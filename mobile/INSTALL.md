# 手机安装与调用

核对日期：2026-10-14。目标是只用手机把本 Skill 保存进 Agent 的技能库，之后换产品仍能调用。这里区分平台官方能力、本仓库提供的文件，以及尚待手机实测的部分。

**当前没有完成这三个平台的手机原生安装实测。不能承诺“任意手机 Agent 发链接就一定装好”。** 电脑 `npx` 安装成功也不能证明手机安装成功。

## 先选你使用的产品

| 手机产品 | 官方可确认的能力 | 本 Skill 的手机安装状态 |
| --- | --- | --- |
| WorkBuddy App／微信腾讯 WorkBuddy | 云端工作不需要个人电脑；手机可通过 SkillHub 安装指令添加技能 | 尚未发布到 SkillHub；GitHub直接安装路线待实测，不伪造SkillHub安装指令 |
| Grok Bot | 手机可给同一云端Bot发任务；官方支持通过对话保存私人技能 | 提供完整载荷与保存请求；保存、资源完整性及新任务调用待实测 |
| 豆包的工作任务／豆包工作入口 | 产品体系支持自定义技能、对话式安装及导入；移动端入口能力可能不同 | 需当前手机账号开放原生技能保存入口；不能把PC导入能力当作手机已支持 |

普通Grok聊天、Grok Build和Grok Bot不是同一个安装目标；普通豆包聊天里读过文件也不等于注册了工作技能。

## 手机要用的文件

- [复制这份安装请求](INSTALL-PROMPT.txt)：发给有原生技能保存能力的Agent，先检查能力，再安装和回报证据。
- [下载完整技能ZIP](https://raw.githubusercontent.com/yetongzhu463-stack/yetong-product-marketing/main/mobile/yetong-product-marketing.zip)：一个技能目录，包含原有9文件，适合平台明确支持技能包导入的入口。
- [下载完整TXT](https://raw.githubusercontent.com/yetongzhu463-stack/yetong-product-marketing/main/mobile/yetong-product-marketing-full.txt)：8份Markdown原文完整合并，适合原生私人技能通过对话保存、或文件附件读取的入口；不是精简提示词。
- [完整性清单](manifest.json)：原有9文件和两个分发文件的SHA-256及字节数。它校验内容，不能替代平台安装成功证据。

可以从手机浏览器保存到系统“文件”，再在Agent的附件入口选择；具体下载、附件格式和大小以当前系统及App为准。若TXT不能作为附件，打开它并复制完整内容；若超出输入或保存上限，停止并报告，不删掉参考规则凑长度。

## WorkBuddy：手机云端入口

官方区分“云端工作”和“连接电脑”，云端工作无需个人电脑；App也支持SkillHub扩展。[官方移动端简介](https://www.codebuddy.cn/docs/workbuddyapp/Overview)

官方已说明的手机技能安装路线是：在SkillHub找到技能，复制其安装指令，发到WorkBuddy；成功后用“+ → 添加技能”选用。[官方小程序技能说明](https://www.codebuddy.cn/docs/workbuddymini/features/Attachments-and-Skills)

**本仓库目前没有SkillHub条目，作者暂不新增该发布渠道。下面是GitHub自定义技能的能力检查／安装请求，不是官方已验证的SkillHub安装指令。**

1. 打开WorkBuddy App，或微信搜索“腾讯 WorkBuddy”小程序；登录并选择“云端工作”。
2. 把[安装请求](INSTALL-PROMPT.txt)发进去，请它确认当前环境能否安装GitHub自定义Skill。
3. 若它报告原生支持，按其实际官方导入流程提供本仓库ZIP，或让它读取完整TXT并保存；不能只把TXT当作本次附件。
4. 检查“+ → 添加技能”是否实际出现“叶童产品营销”或`yetong-product-marketing`，并选择它；再新建云端任务按下方验收。
5. 如果只支持SkillHub来源、列表没有该技能或不能持续加载，就记为“本入口尚未完成安装”，不要宣称纯手机安装已成功。

“连接电脑”另有电脑安装、联网及移动端连接许可等前提；那是手机遥控电脑，不是本教程所追求的纯手机云端安装。[官方多端协同](https://www.codebuddy.cn/docs/workbuddyapp/features/Multidevice)

## Grok Bot：保存为私人技能

官方确认移动端与桌面使用同一账号及云端电脑。[官方手机说明](https://prod.cursor.com/help/grok-bot/mobile) 官方也支持通过自然语言请求保存私人技能，并说明技能库与调用入口。[官方技能说明](https://docs.x.ai/grok-bot/skills-routines-and-automations)

1. 在手机上打开**Grok Bot**并登录，进入要负责产品营销的Bot对话；不要进入普通Grok问答或Grok Build。
2. 发出[安装请求](INSTALL-PROMPT.txt)，并补一句：“请使用Grok Bot原生的私人技能保存机制，名称为叶童产品营销，保留完整规则及必要参考资料。”
3. 它若无法获取链接，下载完整TXT作为附件，或发送全文。要求确认8个区段都被保存或作为持久资源可重载，不能只保存摘要或指向临时附件的失效路径。
4. 让Bot返回原生保存结果、技能库中的名称和再次调用方法，再做下方新任务验收。官方文档提到桌面`/`和Private skills管理入口；**不假定手机界面也有完全相同的菜单**。
5. 若当前手机账号不能完成保存、无法给出可检查结果或资源超限，明确标“待验证／未完成”，不要改成把文件放入`~/.grok/skills`；那不是已确认的Grok Bot私人技能安装路线。

以上是依据官方“对话保存技能”能力提供的本仓库导入请求；不是已生成的“Add to Grok Bot”官方模板分享链接，也未在你的手机账号完成实测。

## 豆包：先进入工作任务，再检查自定义技能入口

官方已说明豆包工作支持自定义技能、对话式安装和本地技能文件导入，同时说明独立端是PC，手机通过豆包或飞书承接，开放范围与功能以当前入口为准。[飞书官方产品说明](https://www.feishu.cn/content/article/7677519271848610746)

1. 打开豆包手机App，进入账号实际提供的“工作／工作任务”相关入口；没有看到时不要照搬PC菜单，也不要在普通聊天里假定已具备技能安装功能。
2. 发出[安装请求](INSTALL-PROMPT.txt)，补充：“请先检查本账号的手机工作入口能否创建个人自定义技能，并把它保存在后续任务能重新调用的技能库里。”
3. 如果当前入口确实支持，按真实界面选择技能导入或原生保存：包导入用ZIP，执行指令与参考资料保存可用完整TXT。哪种格式可用须由当前入口确认；这里不声称豆包手机统一支持ZIP或TXT导入。
4. 检查技能库／“更多技能”（若实际显示）里是否有此技能，保存范围是否完整，再做新任务验收。
5. 没有手机导入或持久保存能力，就明确记为“当前手机入口未完成安装”；普通文件上传、让豆包记住几句规则、电脑本地已安装，均不能当作纯手机原生安装成功。

本仓库不借扣子、Trae、豆包模型API或电脑本地目录冒充豆包App原生支持。手机端完整安装仍需要账号实测。

## 安装后：在新任务里验收一次

先离开安装那条对话，新建任务／对话；选择刚保存的技能，或按平台实际方式指定它。发送：

```text
调用「叶童产品营销」，这次只检查是否能重新加载，不写营销稿。
请说明四类宣发顺序、每天篇数、硬广持续天数、后面三类天数是否已定，以及每篇图片思路的四项。
请确认这些来自已保存技能，而不是只根据当前消息猜测；不能重新加载时明确报告。
```

对照本仓库应得到：C1硬广→C2选择理由→C3使用后感受→C4收款与复购；每天3～4条，硬广两天，后面三类天数未知；每篇图说明主体、文字、真实素材、说明／证明作用。还应保留不编案例、效果、收款、不自行改营销流程等边界。

仅回答上述常识不够：还要有原生技能库条目／保存标识等依据，以及新任务确实重新加载资源的结果。把技能库和新任务截图留存；一句“我记住了／已安装”不能作为唯一凭据。

## 每次换新产品怎么用

```text
调用「叶童产品营销」。这是新的产品，不沿用旧活动事实。
我以什么身份卖什么，谁付款、谁使用；他们的困难和顾虑是……
真实交付、产品优势、我的优势、价格时间、报名入口、可公开素材是……
今天只写3条产品硬广，每条附图片思路。只补问影响这次输出的关键信息。
```

以后更新时，请重新读取本仓库的完整文件并使用平台原生更新机制；已有同名版本先说明差异，保留个人资料，未经确认不覆盖。分发包不会自动更新你账号里的私人技能。

## 本次验证范围

本仓库保留电脑Agent的GitHub安装验证；手机分发文件校验内容完整性，并做兼容载荷的输出回归。**没有把这些记录当作三个手机App原生安装实测。** 平台版本、账号、网络、技能保存上限和功能开放范围都可能改变结果。
